# openmix web v2 — structural patterns from the mixer demo audit

Implements the top structural patterns from `research_notes/Mixer demo audit/demo-audit.md`
(shortlist §11, items 1–4 + staging/safety halves of 7–8) without touching the
backend contract or WS protocol — every new behavior rides on
`connect`/`fader`/`mute`/`param` out, `state`/`meters` in.

## What shipped

1. **Sends-on-fader without the mode trap** (audit #1).
   Aux rail always on screen (LR + one button per bus); tapping a bus flips all
   input faders to sends for that bus, pins the bus master right, tints the whole
   surface in the destination's color (Yamaha-style color ownership), and shows a
   `SENDS → <bus>` banner with EXIT. Entry and exit are the same gesture
   (re-tap, LR, or EXIT). Auto-cue adds the destination to local solos on entry
   and removes it on exit. "Copy LR" seeds sends from the current LR balance.
   Send levels are cached in `localStorage` and pushed via the existing `param`
   cmd as `auxN_level` dB — no protocol change; a backend that rejects the field
   degrades to a local rehearsal cache.
2. **Three-view skeleton** (audit #2, Mackie).
   Overview / Mixer / Channel nav is always visible, active one dark.
   Overview = one health row per channel (live meter, clip dot, fader position,
   mute/solo state, tap-to-jump, per-bus `mix›` shortcut). Mixer = fader banks.
   Channel = selected strip full-screen DSP (big fader + mute-group assignment
   + full Detail panel).
3. **Custom layers day one** (audit #3).
   LAYOUT mode: reorder strips (‹ ›), blank spacers (+gap), reset to backend
   order. Layer tabs renameable, custom layers addable (snapshots current
   strips) and deletable; everything persists in `localStorage`.
   Mute-groups row (G1–G4, tap toggles members, counts shown); assignment chips
   live in Channel view.
4. **Safety** (audit shortlist safety thread).
   MUTE EN master toggle (default armed; when off, all mute buttons lock out
   with an explanation instead of silently doing nothing). FINE mode (drags at
   20%, 0.002 key steps). Tap-a-value exact entry on every fader/send readout
   (modal with slider + numeric + quick buttons). Grow&Glow: the grabbed fader
   scales up, glows, and shows a live value bubble.
5. **Staging meters** (audit #7, half).
   Each strip paints input-behind/output-front on one canvas plus a latched
   CLIP LED; tap the meter to clear. Input is currently a pre-fader estimate
   (`level / fader`) — honest but derived; it becomes exact when the relay
   sends real pre/post frames (see deferred).

Bus detection is canonical on sim geometry (ch ≥ 32) with a `/^bus/i` name
fallback for narrow backends; SoF entry is refused for buses with no aux tap.

## Deferred to the DSP pass (explicitly not this change)

- **EQ graph done right** (audit #5): draggable nodes + RTA overlay, HPF/LPF
  slopes, double-tap reset, pinch-Q. Detail still uses sliders.
- **Fat Channel thumbnails** (audit #4): EQ-curve/GR microviews in strips.
  Strips show meters + clip only; GR meters need relay/engine data first.
- **Scenes with trust machinery** (audit #6): dirty `*`, per-scene scope,
  channel/process safes, undo, hot-scenes, setlists. Slots still snapshot
  fader+mute only.
- **Permanent status strip** (audit #10): scene-dirty, clear-solo, clock,
  connection health, lock in one home. Top bar still has connect/badge/via.
- **Real pre/post meter frames + GR**: needs `serve`/relay + engine work
  outside `apps/web`.
- **Wizards / Simple-vs-Advanced** (honorable mention): no gain/FX/room wizards.
- **Second-view / detachable pane** (LV1 two-window): single viewport only.

## Contract note

`src/lib/backend.ts` and the `:8080` WS JSON protocol are byte-identical to
before. SoF sends reuse `param`; solos stay local (as before); MAIN stays a
local monitor-dim pseudo-strip.
