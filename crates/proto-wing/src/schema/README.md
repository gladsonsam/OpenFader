The FX table contains model-specific protocol facts extracted from
[dannyfiresnake/libwing propmap.jsonl](https://github.com/dannyfiresnake/libwing/blob/74c2ff649aabcc62a788fcf034c41d7d82e40b3c/propmap.jsonl).
Upstream revision: `74c2ff649aabcc62a788fcf034c41d7d82e40b3c`.
The upstream README identifies a WING Compact running firmware 3.0.5 as its source.
The upstream repository LICENSE (Apache-2.0) is retained as LICENSE.libwing.
OpenFader code remains GPL-3.0-or-later.

Only FX slot 1's model descriptions and slot 9's model availability were extracted;
other slots share these definitions. Synthetic model segments in libwing's
fullname values are not sent in OSC paths (manual p.24).
All controls are documentation/schema-based, not hardware-verified in OpenFader.
Do not run wingschema on a working mixer: its enumeration changes loaded models.

Regenerate from a local checkout of the pinned upstream revision with:

```sh
python3 crates/proto-wing/tools/import_schema.py /path/to/libwing/propmap.jsonl
```

The importer retains descending ranges, emits float32-preserving literals,
and omits one-step constant properties rather than presenting fake controls.

`processors.json` is generated from the same pinned propmap by
`python3 crates/proto-wing/tools/import_processors.py /path/to/propmap.jsonl`.
It records family/model-specific writable processor leaf names and domains;
scene capture and recall also check the current console's live definitions.

`processors_31.json` registers WING 3.1 known model rosters using the
3.1-03 Remote Protocols node tables and processor appendix alongside the
pinned 3.0.5 facts. Rebuild with `python3 crates/proto-wing/tools/import_processors_31.py`.
The 3.1 manual contains conflicting hold bounds and some spelling differences;
the generator records bounded unions or explicit alternative rosters. Live DD
must match exactly one registered roster and validate every captured value.
Unknown models, leaves and definitions remain unavailable.

`warm_position5_ids.json` contains native processor-position identities from
the pinned 3.0.5 propmap and is regenerated by
`python3 crates/proto-wing/tools/import_warm_ids.py /path/to/propmap.jsonl`.
WARM 3.1's model-specific `wmix` is accepted only with its model-scoped index,
label and domain, plus the pinned position hash where one exists. Aux dynamics
was not in the 3.0.5 source and has no inferred hash.
